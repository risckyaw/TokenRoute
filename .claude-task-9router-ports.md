=== Feature 1: Earliest Retry-After aggregation on terminal failure ===
9router combo.js: when every candidate 429s, collect Retry-After/reset timestamps from ALL failures and answer with the EARLIEST one plus a human message ("reset after 2m 30s"). TokenRoute relayAllFailed (internal/server/server.go) relays the LAST retryable response — its Retry-After may be the longest while another candidate resets sooner.
Implement:
- During failover, track the earliest known reset time across candidates: from (a) upstream 429 Retry-After headers observed, (b) QuotaLedger WindowReset for quota-locked candidates, (c) circuit OpenUntil for circuit-skipped candidates.
- When the terminal response is an upstream 429 relay (status 429), override/write Retry-After = min(observed resets) when that is sooner than the relayed value; add `X-TokenRoute-Retry-After-Source: upstream|quota|circuit` marker (pick the winning source).
- Human message stays the upstream body — do NOT rewrite it (TokenRoute relays raw bodies by design).
- Tests: three-candidate scenario with distinct resets picks earliest; relayed Retry-After shorter than any computed stays; non-429 terminal untouched.

=== Feature 2: Sticky round-robin ===
9router getRotatedModels(stickyLimit): round-robin advances only after N consecutive requests on the same model. TokenRoute round_robin rotates per request — hostile to provider prompt caches.
Implement:
- Route config: `sticky: N` (int, default 1 = current behavior) on routes using round_robin strategy.
- Router keeps per-route {index, count} state; after N consecutive dispatches on index, advance to next. Wraps. Config reload (SIGHUP) resets state.
- Interacts correctly with circuit/quota filtering: sticky index points into the ORIGINAL candidate list; filtered candidates are skipped in-order from the sticky start.
- Tests: rotation after exactly N, wrap-around, filtered candidate skip, N=1 unchanged.

=== Feature 3: Capability-aware routing from request body ===
9router detectRequiredCapabilities + reorderByCapabilities. TokenRoute catalog (internal/catalog/catalog.go) already stores per-model Modalities (image/pdf/audio/video inputs) synced from models.dev, but routing never uses them: a request containing an image can be routed to a text-only model and 400.
Implement:
- internal/router/capabilities.go: DetectRequiredModalities(body []byte) — scan chat-completion messages for content blocks: type image_url/image/input_image → "image"; input_audio/audio_url/audio → "audio"; file/document/input_file → inspect embedded mime (data: URI media_type / source.media_type / file_data prefix); mime image/*→image, application/pdf→pdf, audio/*→audio, video/*→video; bare file without mime → pdf (9router fallback).
- Candidate reordering in OrderCandidates (before strategy ordering, after tag filter): tier 0 = candidate's catalog modalities cover all required; tier 1 = rest. Stable sort (never drops a candidate — unknown model = no catalog entry = tier 0 ONLY when no modalities required, else tier 1 with a comment explaining the safe-floor choice: unknown models can still serve text-only requests but go last when media is required).
- Catalog lookup needs provider+model → modalities: wire the catalog data into Router (check how catalog sync already exposes entries; reuse).
- Decision header: append `;caps=image` listing detected requirements (only when non-empty).
- Tests: image block detection, data-URI mime, bare file → pdf, stable tiering, unknown-model handling, empty requirement no-op, header marker.

=== Feature 4: failure_rules — ordered text/status rules with per-rule cooldown ===
9router errorConfig.js ERROR_RULES: ordered rules, text-substring first then status, each rule → fixed cooldownMs OR exponential backoff (base 2s, ×2/level, cap 5min). TokenRoute has disable_keywords (new-api port) and FailureKind classification, but cooldown durations are circuit-global.
Implement:
- Config top-level `failure_rules: [{match: "overloaded", cooldown_ms: 4000}, {match: "rate limit", backoff: true}, {status: 401, cooldown_ms: 120000}]`. Ordered evaluation: text rules in order (case-insensitive substring on the error body), then status rules. First hit wins.
- Outcome: Router.OpenCircuitFor(provider, duration) with the rule's cooldown; `backoff: true` uses per-provider escalating level (2s,4s,8s… cap 5min; level resets on success — reuse/extend existing escalation machinery if suitable, else a small level map).
- Rules without match/status are config errors (fail load). When failure_rules is unset, current classification+circuit behavior is EXACTLY preserved.
- Interaction: a matching rule overrides the default cooldown for that failure; classification (FailureKind for metrics/allowed_fails) still runs unchanged.
- Tests: text-first ordering, status fallback, backoff escalation 2→4→8s + cap + reset on success, invalid rule rejected, unset = legacy behavior.

=== Feature 5: fusion_judge strategy (panel + judge synthesis) ===
9router handleFusionChat: fan the prompt to N panel models (non-stream, tools stripped, tool history flattened to prose), collect with quorum + straggler grace, then ONE judge model synthesizes the final answer from all panel answers (analysis prompt: consensus/contradictions/blind spots, sources anonymized "Source N"). Graceful: 0 answers → 503; exactly 1 → answer directly.
Implement as new strategy `fusion_judge` in internal/server (alongside existing fusion.go):
- Route config: `strategy: fusion_judge` with `fusion_judge: {judge: "provider/model", min_panel: 2, grace_ms: 1500, timeout_ms: 60000}`; candidates of the route = the panel. judge defaults to first candidate. Non-stream client requests: panel calls non-stream (stream:false, strip tools/tool_choice/stream_options from panel bodies, flatten tool/function messages to assistant prose with "[Tool result: ...]"/"[Called tools: ...]" prefixes — port flattenToolHistory).
- Collect: wait until minPanel successes, then grace_ms for stragglers, hard cap timeout_ms (context deadline per panel call too).
- Judge body = original body + appended user turn containing the judge prompt (English template in code; anonymize as Source 1..N with each source's full text).
- Judge call honors the client's original stream flag (stream the judge if client asked stream).
- 0 panel answers → 502 (all failed — follow existing relayAllFailed semantics); exactly 1 → relay that answer directly (re-issue to that model WITH original body incl. tools/stream, like 9router's handleSingleModel(body, model) direct path).
- Metering: usage log rows for EVERY panel call + the judge call (each with its real provider/model/tokens/cost); decision header `;fusion=judge;panel=N;answers=M`.
- Context-window guard, circuit breakers, quotas apply to panel candidates and judge as usual (panel candidate circuit-open → excluded from fan-out).
- Tests: full flow with fake providers (2 ok 1 slow → quorum+grace), 1 answer direct path, 0 answers 502, tool flattening, judge receives anonymized sources, usage rows counted, header markers. Keep the judge prompt template compact.

=== Feature 6: DeepSeek balance probe → pre-emptive quota marking ===
9router usage/deepseek.js: GET https://api.deepseek.com/user/balance with the provider key returns balance_infos[]. TokenRoute discovers empty balance only via a 429 mid-traffic.
Implement:
- Provider config: `balance_probe: {url: "https://api.deepseek.com/user/balance", interval_ms: 300000, min_usd: 0.10}` (opt-in per provider; url explicit so it works for any provider exposing a DeepSeek-style balance endpoint).
- Background goroutine (same lifecycle as health checks): GET url with the provider's key, parse balance_infos[].total_balance (string number), sum across currencies when >1 (or take first — document choice).
- Below min_usd → mark the provider: circuit OpenFor(remaining interval) is wrong semantically; instead set a quota-ledger-style "balance_low" flag that quota-aware strategies treat as exhausted (check how QuotaLedger exhaustion integrates and mirror it), and log WARN. Recovery: next probe above threshold clears it. Probe failures (network/401) just log.
- Decision header/admin visibility: expose flag in existing admin providers endpoint if there is one (check dashboard API), else log only.
- Tests: parse balance_infos variants, below-threshold marks + strategies skip, above-threshold clears, probe error no-op, disabled default.
